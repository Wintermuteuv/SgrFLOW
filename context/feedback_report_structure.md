При подготовке отчёта по любой команде блока разработки использовать эту двухуровневую структуру.

**Why:** Иван утвердил этот формат на VMS-команде и хочет одинаковый формат у всех команд блока для сопоставимости. Деловую часть смотрит руководитель за 3–4 минуты, технические детали — приложением.

**How to apply:** при поступлении новых вводных (доска + репо + период) собирать оба документа сразу.

---

## Executive Summary (1–2 страницы, .docx)

1. **Главное за период** — 1–2 абзаца про доставленную бизнес-ценность (НЕ про код). Тематические блоки, ключевые milestone-выпуски.
2. **Ключевые показатели** — таблица из 6 строк: закрыто задач (с разбивкой эпиков/ошибок), % Critical-задач, активных разработчиков, Ready 4 Deploy, всего в пайплайне, спринтов/милестоунов завершено.
3. **Доставленные бизнес-ценности** — 5–8 буллетов: жирный заголовок темы + 1 предложение бизнес-эффекта.
4. **В пайплайне на следующий период** — таблица «Направление / Состояние / Зачем бизнесу», 3–5 строк + строка "N тикетов Ready 4 Deploy".
5. **Точки внимания** — 2–4 пункта (bus-factor, гигиена коммитов, доля хотфиксов, процессные пробелы). Факт + рекомендация, без претензий.
6. **Источники** — ссылки на доску(и) и репозиторий(и), упоминание о приложении-техотчёте.

## Технический отчёт (детальный, .docx)

1. Краткая сводка (таблица)
2. Метрики по типу / приоритету / спринту / исполнителю
3. Активность в репозитории (по авторам, активные дни, %)
4. Связка задач и коммитов:
   - Топ тикетов по числу коммитов
   - WIP-тикеты (с коммитами, но не закрытые)
   - (опционально) Тикеты с/без коммитов в репо
5. Ключевые тематические направления (нумерованный список)
6. Наблюдения и рекомендации (буллеты)
7. Источники (включая JQL и API-запросы)

## Артефакты — что отдавать пользователю

- `{{Команда}}_Executive_Summary_{{период}}.docx` — для руководства
- `{{Команда}}_Отчёт_{{период}}.docx` — детальный, как приложение
- `{{Команда}}_analysis_{{период}}.md` — markdown-версия для архива
- `jira_issues_{{период}}.tsv` — сырые данные из Jira

## Визуальные правила (для согласованности всех команд)

- Шрифт Arial, размер 22 (11pt) для основного текста, 20 (10pt) для таблиц
- Цвета: H1 = #1F4E79, H2 = #2E75B6, заливка таблиц-заголовков = #1F4E79 (белый текст), zebra = #F2F6FB
- A4, поля 2 см, колонтитул `Отчёт направления X · период`, нумерация страниц снизу по центру
- Готовые скрипты сборки лежат в outputs: `build_report.js` (тех.), `build_exec.js` (executive), `build_template.js` (пустой шаблон)
