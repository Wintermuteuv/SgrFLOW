# SgrFLOW — Концепция

## Проблема

В компании с несколькими продуктами и командами никто не видит полной картины:
- Какой продукт кто курирует?
- Какие проекты сейчас активны и кто в них?
- Где зависимости между продуктами?
- У кого самая высокая нагрузка?

Эта информация есть — она рассыпана по Jira, Confluence, чатам и головах руководителей.

## Решение

Единая страница с живым графом связей. Не отчёт, не таблица — **интерактивная карта компании**.

## Пользователи

| Роль | Что получают |
|------|-------------|
| Руководитель направления | Обзор загрузки людей и приоритетов проектов |
| Продакт-менеджер | Видит зависимости между продуктами |
| Разработчик | Понимает, кто ещё работает на смежных проектах |
| HR | Карта команд и ответственностей |

## Принципы дизайна

1. **Одна страница** — никаких вложенных навигаций
2. **Живые данные** — граф обновляется из источников, не вручную
3. **Размер = важность** — приоритет считывается моментально
4. **Клик = детали** — не перегружать граф, раскрывать по запросу

## Архитектура (целевая)

```
Источники данных          Бэкенд (опционально)     Фронтенд
─────────────────         ──────────────────        ─────────
Jira REST API      ──→
GitLab REST API    ──→    graph-builder.js   ──→    3d-force-graph
Google Sheets      ──→    (Node / Python)           + React UI
HR система         ──→
```

MVP — без бэкенда: JSON-файл правится вручную или через Google Sheets.

## Сессия прототипирования (2026-06-06)

Прототип собран за одну сессию с Claude (Cowork mode):
- Библиотека: `3d-force-graph@1.73.0` (CDN)
- Демо-данные: 8 людей, 4 продукта, 6 проектов, 22 связи
- Функции: 3D-физика, фильтры по типу, клик → инфо-панель, размер = приоритет
