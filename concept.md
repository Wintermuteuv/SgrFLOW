# SgrFLOW — Концепция

## Проблема

В компании с несколькими продуктами и командами (~800 человек) никто не видит полной картины:

- Какой продукт кто курирует?
- Какие проекты сейчас активны и кто в них?
- Где зависимости между продуктами?
- У кого самая высокая нагрузка?

Эта информация есть — она рассыпана по Jira, Confluence, чатам и головах руководителей.

-----

## Решение

Единая страница с живым графом связей. Не отчёт, не таблица — **интерактивная карта компании**.

-----

## Пользователи

|Роль                    |Что получают                               |
|------------------------|-------------------------------------------|
|Топ-менеджмент          |Org chart, spans of control, иерархия      |
|Руководитель направления|Обзор нагрузки людей и приоритетов проектов|
|Product Owner / CTO     |Состав команд по продуктам, зависимости    |
|Project Manager         |Состав проектов, стейкхолдеры, блокеры     |
|HR                      |Карта команд, ответственностей, перегрузка |

-----

## Принципы дизайна

1. **Одна страница** — никаких вложенных навигаций
1. **Живые данные** — граф обновляется из источников, не вручную
1. **Размер = важность** — приоритет считывается моментально
1. **Клик = детали** — не перегружать граф, раскрывать по запросу
1. **POV** — каждый пользователь видит граф со своей точки зрения
1. **Ego network** — наведение на узел выделяет его связи, гасит остальное

-----

## POV-режимы

Переключатель точки зрения меняет: какие узлы показываются, какие связи активны, какая физика/раскладка.

|POV         |Аудитория         |Центр графа|Активные связи                          |Раскладка                |
|------------|------------------|-----------|----------------------------------------|-------------------------|
|**Продукт** |Product Owner, CTO|Продукты   |owns, member_of, for_product, depends_on|Кластеры вокруг продуктов|
|**Человек** |HR, Delivery      |Люди       |reports_to, manages, member_of, owns    |Свободная физика         |
|**Проект**  |PM, руководитель  |Проекты    |decides, stakeholder, member_of, blocks |Кластеры вокруг проектов |
|**Иерархия**|Топ-менеджмент    |—          |reports_to, manages                     |Дерево (org chart)       |

## Схема данных

### Person

```json
{
  "id": "ivan",
  "name": "Иван Божитов",
  "type": "person",
  "company": "Sergek",
  "department": "Delivery",
  "role": "CDO",
  "reportsTo": "ceo_id",
  "functions": ["delivery governance", "architecture oversight"],
  "processes": ["релизный цикл", "планирование спринтов"],
  "priority": 5,
  "status": "active"
}
```

### Project

```json
{
  "id": "p1",
  "name": "Отчёты Q2",
  "type": "project",
  "status": "active",
  "investment": "M",
  "decisionMaker": "ivan",
  "stakeholders": [
    { "id": "ceo_id", "type": "internal" },
    { "id": "client_id", "type": "external" }
  ],
  "outcomes": "Описание перспектив",
  "priority": 4
}
```

### Product

```json
{
  "id": "vms",
  "name": "VMS",
  "type": "product",
  "domain": "surveillance",
  "owner": "ivan",
  "linkedProjects": ["p1", "p2"],
  "priority": 5
}
```

### Links

```json
{ "source": "ivan", "target": "p1", "type": "owns" }
```

## Типы связей

|type          |между кем               |смысл                            |визуал             |
|--------------|------------------------|---------------------------------|-------------------|
|`reports_to`  |Person → Person         |административное подчинение      |тонкая, серая      |
|`manages`     |Person → Person         |функциональное руководство       |средняя, синяя     |
|`collaborates`|Person ↔ Person         |горизонтальная связь             |тонкая, пунктир    |
|`owns`        |Person → Product/Project|владение / ответственность       |толстая, синяя     |
|`member_of`   |Person → Project/Product|участие                          |тонкая, серая      |
|`decides`     |Person → Project        |принимает решение                |средняя, фиолетовая|
|`stakeholder` |Person → Project        |стейкхолдер (+ internal/external)|пунктир, зелёная   |
|`for_product` |Project → Product       |проект обслуживает продукт       |средняя, зелёная   |
|`depends_on`  |Product → Product       |межпродуктовая зависимость       |пунктир, оранжевая |
|`blocks`      |Project → Project       |блокирует                        |толстая, красная   |

-----

## Нагрузка (load)

Считается автоматически, не хранится в JSON:

```
load(person) = owns × 2 + member_of × 1
```

Цвет узла: ≤3 → зелёный · 4–6 → жёлтый · 7+ → красный

|-------------------------|--------------|-------------|

## Архитектура (целевая)

```
Источники данных          Бэкенд (опционально)     Фронтенд
─────────────────         ──────────────────        ─────────
HR система         ──→
Jira REST API      ──→    graph-builder.js   ──→    3d-force-graph
GitLab REST API    ──→    (Node / Python)           + React UI
Google Sheets      ──→                              + POV switcher
```

MVP — без бэкенда: `data.json` правится вручную или через Google Sheets.
